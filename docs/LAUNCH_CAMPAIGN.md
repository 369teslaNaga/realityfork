## Launch message: show the experiment, not just the repository

1. Open the lab. Click **Try Moon gravity**. Show the original synthetic trajectory alongside the alternate Moon-gravity trajectory.
2. Switch to MaterialFork and WindFork to change the assumptions. Export a Reality Card.
3. Show exactly what is and is not real. The reference is **synthetic**. The forked trajectory is a **2D simulation**, not an AI-modified video.
4. Share the 15-second video and a direct link to the working demo, then the GitHub code. Make the first 3 seconds visual.
5. Ask for feedback on one technical problem, such as tracking low-contrast objects. Avoid generic "please star" appeals.

## Checklist before external launch

- Open the public site on desktop and mobile with a fresh/private window. Test Moon, Material, Wind, exports, and console errors.
- Confirm the teaser is clearly synthetic and does not imply true 3D reconstruction.
- In GitHub **About** (gear icon), set **Website** to https://369teslanaga.github.io/realityfork/ ; set repository topics: `physics`, `simulation`, `javascript`, `open-source`, `video-analysis`, `education`, `counterfactual`, `local-first`.
- In GitHub **Settings > General**, choose **Social preview**, upload `assets/social-preview.png` if it is not already configured; README images do not automatically configure the repo social preview.
- Pin the project to your GitHub profile after the first public launch, if you want it featured.

## Creator-owned launch sequence (IST)

**Today — proof and first users:** publish a genuine screen recording to X and LinkedIn, link to live demo and source, and invite five independent people to test it. Answer the first comments in your own voice.

**Next — technical community:** only after the public demo is confirmed usable by strangers, submit a **Show HN** yourself. Proposed factual title to adapt: `Show HN: RealityFork – a browser physics lab to change gravity in a ball simulation`. Write your *own* first comment with why you built it, the 2D physics approach, limitations, and what feedback you need. Hacker News rules do not permit AI-generated/AI-edited posts or coordinated votes.

**Next 48 hours:** post an honest technical article or screen capture in relevant communities where project sharing is permitted. Answer questions, log bugs, and improve the demo. Do not spam many unrelated communities.

**Week one:** publish a small real-world calibration validation experiment and a testable changelog; highlight improvements rather than a fabricated achievement.

## Measure genuine interest

Track GitHub traffic unique visitors, demo link clicks, independent tester feedback, issue reports, genuine stars/forks and returning contributors. The first goal is a compelling demo and useful feedback — **viral reach cannot be promised or bought**.

Never purchase stars, ask for reciprocal votes, fabricate scientific accuracy, or claim synthetic footage came from a real camera.
